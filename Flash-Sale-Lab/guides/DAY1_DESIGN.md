## 오전 1 — 요구사항 정의

`templates/ARCHITECTURE.md`를 복사해 채우기 시작.

1. **기능 요구사항**을 동사로 5~8개. (조회/세일시작/주문/재고소진 실패/주문상태 확인 ...)
2. **비기능 요구사항을 숫자로** — 아래를 반드시 확정:
   - 목표 동시 요청 수 (예: 500 → 1,000 → 2,000 단계)
   - P99 지연 목표 (예: ≤ 300ms)
   - 정합성 규칙: **재고 초과판매 0건**
   - 가용성: 브로커 1개 죽어도 주문 지속?
   - 관측: 무엇을 볼 것인가

> ✅ 체크: 목표가 전부 **측정 가능한 숫자**인가? 이게 Day 3 합격 기준이 된다.

## 오전 2 — 핵심 설계 결정

[트레이드오프 체크리스트](TRADEOFFS_CHECKLIST.md)를 열고, 최소 아래 3개를 결정 + [결정 로그](../templates/DECISION_LOG.md) 작성:

- [ ] **A1. 재고 차감 방식** (DB 락 / Redis 원자연산 / 낙관적 락)
- [ ] **B1. 동기 vs 비동기** — ※ 지시: **동기로 시작**한다고 결정하고, "부하로 깨지면 비동기 전환" 가설을 세워라
- [ ] **B2. 브로커 선택** (Day 3 A/B용으로 Kafka 예정)

여유되면: 실패 처리(B3), 단일 신뢰 지표(D2), AIOps 대상(E1)도.

> 💡 각 결정 로그는 `문제 / 대안 / 트레이드오프 / 결정 / 근거` 5줄. 근거는 반드시 **비기능 목표와 연결**.

## 오후 1 — 아키텍처 다이어그램

1. C4로 위에서 아래로: Context → Container ([설계 가이드 §2](DESIGN_GUIDE.md))
2. Mermaid로 `ARCHITECTURE.md`에 그린다 (버전관리됨). 예시는 설계 가이드 §3.
3. 각 화살표에 **동기(실선)/비동기(점선)**와 데이터 표시
4. **SPOF를 표시**하고, 어떻게 없앨지 메모 (Day 3 A/B로 검증)

> ✅ 체크: 재고 정합성을 지키는 지점이 그림에 명확히 보이는가?
