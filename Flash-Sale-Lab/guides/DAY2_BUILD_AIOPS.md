## 오전 1 — MVP 앱 (동기 버전)

가장 단순하게. **바이브코딩 OK** (AI에게 시켜라).

- 엔드포인트: `GET /products`, `POST /sale/start`, `POST /purchase`, `GET /purchase/{id}`
- `POST /purchase`: 재고 확인 → 차감 → 주문 저장 → 응답 (전부 동기)
- `/metrics` 노출 (Prometheus 포맷) — 주문 성공/실패 카운터, 지연 히스토그램

> 💡 앱 코드 품질에 시간 쓰지 마라. "돌아가고 메트릭이 나오면" 충분.

## 오전 2 — 재고 정합성 구현 + 검증

Day 1의 A1 결정대로 구현.

- [ ] 동시 요청에서 초과판매가 안 나는지 **작은 부하로 검증**: 재고 100개에 동시 200 요청 → 정확히 100건 성공?
- [ ] 안 지켜지면? → 락/원자연산 다시 (여기가 첫 번째 설계 검증 포인트)

```bash
# 빠른 동시성 테스트 (k6 or 간단 스크립트)
k6 run --vus 200 --iterations 200 k6/purchase.js
# 성공 응답 수 == 재고 수 인지 확인
```

## 오후 1 — 관측 스택

`docker-compose.yml`에 증분 추가:
- [ ] Prometheus (앱 `/metrics` 스크랩)
- [ ] Grafana (대시보드: RPS, P50/P95/P99, 에러율, 주문 성공/실패)
- [ ] (선택) Loki + 앱 로그 수집

> ✅ 체크: Grafana에서 **P99와 에러율을 눈으로** 볼 수 있어야 Day 3 부하테스트가 의미있다.

## 오후 2 — 비동기(Kafka) 버전 추가

동기 버전은 그대로 두고, **큐 버전을 나란히** 만든다 (A/B용).
- [ ] Kafka + Zookeeper를 compose에 추가 (먼저 **단일 broker**)
- [ ] `POST /purchase` → Kafka에 주문 이벤트 발행 → "접수됨" 즉시 응답
- [ ] 컨슈머가 이벤트 소비 → 재고 차감 → DB 저장
- [ ] 실패 처리(B3 결정대로): 재시도 → DLT
- [ ] 환경변수/프로파일로 동기/비동기 전환 가능하게 (A/B 비교를 위해 두 버전을 나란히)

> ⚠️ 흔한 함정 미리 피하기: 컨슈머 그룹 등록 race, 메시지 순서, 중복 처리(멱등성) 고려.

## 오후 3 — AIOps 자동화 1개 (★ 우리 차별화)

[트레이드오프 E1](TRADEOFFS_CHECKLIST.md#e-aiops-자동화-우리-차별화)에서 고른 것 하나를 **실제로 동작**하게. 최소 하나:

**옵션 A — 로그/메트릭 이상 요약 (추천 입문)**
- Prometheus/Loki에서 최근 이상(에러 급증·지연 튐) 쿼리 → LLM이 "무슨 일이 일어났고 원인 후보"를 요약 → 콘솔/슬랙 출력

**옵션 B — 데일리 리포트 파이프라인**
- 소스 수집(Git 로그 + 결정 로그 + 회의 메모 + 할일) → LLM 종합 요약 → 마크다운/슬랙 발행
- [데일리 리포트 템플릿](../templates/DAILY_REPORT.md) 형식으로

**옵션 C — 이상탐지 → 알림**
- 에러율/지연 임계 초과 감지 → LLM이 심각도 판단·설명 붙여 알림

> 💡 `aiops/` 폴더에 스크립트로. 실전 AIOps 자동화의 PoC가 된다.
